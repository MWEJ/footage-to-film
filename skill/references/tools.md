# Tools

`check-tools.sh` finds these and tests each by running it. It writes what it found to `film-project/logs/tools.json`, which every script and the edit's own commands read. A tool check must judge a tool by running it and reading its exit status directly: a check that pipes the tool into `head`, or captures it in `$(…)`, reports the wrong status.

| Tool | Used for | Notes |
|---|---|---|
| ffmpeg-full | converting, strips, mastering, the final checks | Homebrew's plain `ffmpeg` is a slim build without `drawtext` and other filters. Use `/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg`. Give every ffmpeg call no standard input (`< /dev/null`), or it swallows a loop's input. `libplacebo` does not run on this Mac: there is no Vulkan driver. |
| whisper.cpp | transcripts | `whisper-cli -m <model> -f speech16k.wav -l en -ojf -of out -ml 1 -sow -nfa -dtw large.v3.turbo` gives one entry per word, with an alignment time for each token. Feed it 16 kHz mono WAV. Word times taken from the alignment are good to about a fifth of a second: enough for captions, not for type that must land on a syllable. Without `-dtw` they were up to 0.6 s off on real speech, and a full second early after a silence. In this mode whisper prints every entry over and over; do not keep its output. It can invent words on clips with no speech (on a steady tone it wrote "Transcription by CastingWords"); `transcribe.mjs` marks a phrase doubtful when whisper gave one of its tokens a probability under 0.1. The model is `~/.local/share/whisper.cpp/models/ggml-large-v3-turbo.bin`. |
| exiftool | dates, places, photo sizes | `-n` gives plain numbers. |
| uv | Python for photos and music | Always `uv run --python 3.12 --with …`: the user has conda first on the PATH, so a bare `python` is not the one you expect. |
| Node 20 or later | the scripts and the edit | The scripts use only built-in modules. |
| Swift | finding faces | `swift SKILL/scripts/faces.swift "<footage>"` uses macOS's Vision framework; nothing is installed or downloaded. The script is compiled on every run, which takes a few seconds. It prints a deprecation warning that can be ignored. |
| Demucs | finding a voice in a music candidate; the song's four stems | `~/.local/bin/demucs --two-stems vocals -d mps -o OUT track.flac`. Used by `music-screen.py` (`--no-vocals` skips it) and by `music-stems.mjs`, which splits the film's song into vocals, drums, bass and other (`-n htdemucs`, on `mps`, else the CPU) and makes `other` so that the four sum to the song. Its model (htdemucs, 84 MB) must be on this Mac: Demucs 4.1 keeps it in the Hugging Face cache (`~/.cache/huggingface/hub/models--adefossez--HTDemucs/`, `955717e8.safetensors` beside `htdemucs.yaml`), earlier versions as `955717e8-8726e21a.th` in `~/.cache/torch/hub/checkpoints/`. Both scripts look in both places, and run Demucs offline (`HF_HUB_OFFLINE=1`) so it fetches nothing. Without the model the screen skips the voice and `music-stems.mjs` stops; after the user has agreed to the download, `--fetch` on either lets Demucs fetch it. |
| `originals.mjs` | are the original clips and photos still where the inventory has them? | `node SKILL/scripts/originals.mjs "<footage>"`. Reads only. Fails when one is missing or has changed size; names files that are in the folder but not in the inventory. Run it before saying that anything can be deleted, and when the user added or moved footage. |
| `grid.mjs` | a clip's frames or a photo under a ten-by-ten grid | `node SKILL/scripts/grid.mjs "<footage>" <clip or photo id> [seconds ...]` writes `review/grid/<id>.jpg`. Lines are tenths of the picture, so a point reads as `focus: [x, y]`. For what `faces.swift` does not find: a cake, a dog, a view. |
| `transcribe.mjs --force` | transcribing every clip again | A clip that has a transcript keeps it otherwise. Use it once on a project transcribed before word starts were improved (a word now starts 0.45 s before its first token's time, never before the word before it ended). |
| `music-grid.py`, `music-arrange.py` | a song's tempo and bars; the song cut to the film | Python through uv: `uv run --python 3.12 --with librosa --with soundfile python SKILL/scripts/music-grid.py "<footage>" song.wav` and `uv run --python 3.12 --with soundfile --with numpy python SKILL/scripts/music-arrange.py "<footage>"`. See `music.md`. |
| ACE-Step | generating music takes | At `~/code/ACE-Step-1.5`, run with its own Python (`.venv/bin/python`). Driven by `music-takes.py`. |
| Remotion 4.0.532 | the edit and the render | Pinned in `edit/package.json`. Its browser (about 190 MB) lives in `node_modules/.remotion`; `new-film.mjs` clones the kit's installed packages, so nothing is downloaded per film. Free for individuals and companies of up to three people. |

Remotion's documentation is available as Markdown: `https://www.remotion.dev/docs/<page>.md`.
